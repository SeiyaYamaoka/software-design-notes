# SOLID

## 一言でいうと

オブジェクト指向設計で、変更しやすく保守しやすい構造を考えるための5つの原則です。

## 5つの原則

- **単一責任の原則（SRP）**: 変更理由が異なる責務を分ける
- **開放閉鎖の原則（OCP）**: 既存コードの変更を抑えながら機能を拡張できるようにする
- **リスコフの置換原則（LSP）**: 派生型を基底型として扱っても期待する動作を壊さない
- **インターフェース分離の原則（ISP）**: 利用側に不要な操作への依存を強制しない
- **依存性逆転の原則（DIP）**: 具体的な実装ではなく抽象に依存する

## 注意点

原則を適用すること自体が目的ではありません。抽象化や分割を増やすほど理解しやすくなるとは限らないため、変更の可能性やコードの規模を踏まえて判断します。
